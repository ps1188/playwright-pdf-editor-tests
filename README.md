# Playwright Tests for the PDF Editor

My first test-automation project. I am a manual QA engineer (10+ years)
learning automation. These tests check my own PDF Editor web app with
**Playwright + TypeScript**.

## What this project proves

- I can write automated UI tests in TypeScript, not just run manual cases.
- I use the **Page Object Model**: selectors live in one class
  (`pages/PdfEditorPage.ts`), tests read like manual test cases.
- I use role-based selectors (`getByRole`, `getByLabel`) instead of
  brittle CSS/XPath, and I wait for real app state instead of fixed sleeps.
- I test what the app **actually does** — every test was run against the
  real app, and I did not fake a pass.

## What the app under test can (and cannot) do

The app tested here is the **V1 export** of my PDF Editor
(`app/pdf-editor.html`, also served from `~/workspace/your_files/pdf-editor/`).
It can: open PDFs, go to the next/previous page, draw, highlight, add text,
erase, undo, clear a page, scan images into a PDF, and save the edited PDF.

It does **not** in this export have OCR, text replacement, or Office
(DOCX/XLSX) conversion — those were added to the app later and are not in
this file. So there are no tests for them here. Adding them is a good
next project once the newer export is available.

The app normally loads pdf.js and pdf-lib from a CDN. For tests, those
libraries are **vendored locally** in `app/vendor/` (the exact same
versions, pdf.js 3.11.174 and pdf-lib 1.17.1), and
`scripts/prepare-app.mjs` builds `app/pdf-editor.local.html` — the real
app with only the library URLs swapped to local files. The tests open
that copy, so **the test run itself needs no internet** (only
`npm install` does).

## How to run it

```bash
# 1. Install Node.js 20 or newer (check with: node -v)
# 2. Install dependencies
npm install

# 3. Install the Chromium browser Playwright drives
npx playwright install chromium

# 4. Generate the sample PDF used by the upload tests
npm run generate-fixture

# 5. Run the tests (starts the local server for you)
npm test

# 6. See the HTML report
npm run test:report

# Optional: watch the tests run in the browser
npm run test:ui
```

No manual step is needed to start the app: `playwright.config.ts`
runs `scripts/prepare-app.mjs` (builds the offline copy of the app)
and then `scripts/serve.mjs`, a tiny Node server that serves the PDF
Editor on http://localhost:4173.

## What each test file teaches

| File | What it covers | What it teaches |
|---|---|---|
| `tests/app-loads.spec.ts` | App loads, empty state, toolbar, sidebar tools, disabled buttons | Smoke tests, `getByRole`, `toBeDisabled()` |
| `tests/open-and-navigate.spec.ts` | Upload a 2-page PDF, page 1/2, Next/Previous, disabled at the ends | `setInputFiles()` on a hidden input, waiting for real state |
| `tests/annotate.spec.ts` | Pick Draw/Highlight/Text, text input appears, drawing enables Undo | Tool state, mouse actions on a canvas, `toHaveClass()` |
| `tests/save-and-export.spec.ts` | Save disabled until a file is open, Save downloads `*-edited.pdf` | Capturing a download with `waitForEvent('download')` |
| `tests/scan.spec.ts` | Scan 1 image → 1-page `scanned-pages.pdf`, 2 images → 2 pages, Save downloads `scanned-pages-edited.pdf` | `setInputFiles()` on a hidden input, multi-file upload |

`pages/PdfEditorPage.ts` is the Page Object — one class holding every
selector and the common actions (`goto()`, `openPdf()`, `selectTool()`,
`drawStroke()`). If a button label changes, fix it there once.

`tests/fixtures/sample-2-pages.pdf` is generated by
`scripts/generate-fixture.mjs` (using pdf-lib). Regenerate it any time
with `npm run generate-fixture`.
